# Bounded CI wait annotations

Authority: jocasta:715251cbbbfd43882e02587a54b70caa@1. Local implementation, provisional until both dependent independent reviews accept.

Terminal workflow-run waits and PR checks-passed waits enrich LastOutput before settlement is saved. Status, conclusion, outcome, reason, exit code and the existing machine trailer remain authoritative. Annotation bodies never enter trailer fields. Registration ReadGitHub probes, pending polls and persisted settled replay make zero enrichment calls. Other PR wait states retain their existing behavior.

The initial status request adds supported gh run view databaseId/attempt/headSha or gh pr view headRefOid fields. Its URL identifies the actual repository selected by explicit --repo or existing directory semantics. Only canonical HTTPS github.com target URLs with matching numeric run/PR identity and explicit repository binding are enriched. Unsupported enterprise hosts produce annotations unavailable without changing existing gate evaluation. No repository selection, trust, config, provider, quota or task-control behavior changes.

Run annotations use the exact /actions/runs/{id}/attempts/{attempt}/jobs endpoint. Each job must bind the evaluated run and head; a present run_attempt must match. A canonical api.github.com repository check_run_url is parsed for its numeric ID, then a constructed fixed repository endpoint is used. Metadata ID/head/count are checked. PR annotations enumerate check runs on the evaluated head, filter=all, and match each evaluated CheckRun by name, details URL, status, conclusion, started/completed timestamps. Matching must be unique; duplicate reruns or ambiguous bindings refuse enrichment. Older reruns and unrelated checks never supply annotations. StatusContext-only diagnostics are unavailable; mixed contexts are partial. Pending checks on a terminal failed PR gate are explicitly unavailable within that partial enumeration.

Check metadata is rechecked after its annotation pages; the target snapshot is rechecked after collection. A changed head/attempt/check snapshot discards the collection, reports unavailable and preserves the original verdict. These consistency calls use constructed gh api requests: one REST run read or one fixed GraphQL PR query with at most100 contexts and explicit hasNextPage refusal, avoiding hidden CLI lookups/pagination. They share the same bounded enrichment budget; there is no new status poll or replay diagnostic fetch. PR results are snapshot observations, not a claim that the remote state cannot change after observation.

Bounds: one <=30-second context; <=20 extra calls including final status recheck, with the last call reserved for that check. Transport stdout <=256KiB per response; aggregate enrichment stdout <=2MiB, passed as the remaining ceiling to the real process transport. Errors conservatively charge a full response ceiling; stderr has an independent 4096-byte process buffer and is never included in annotation output. No gh --paginate, arbitrary API URL following, logs or raw_details. All commands use argument arrays and authenticated gh transport. Enumerations use per_page=50, <=3 pages, <=20 selected checks and <=150 annotation records total. Check metadata is collected together with its annotations so enumeration cannot consume every call before useful evidence.

Output <=4000 UTF8 bytes, <=10 inline records, with check ID/name, severity, repository path/line range, clipped title/message and validated check details links. Observed severity counts are complete only after full enumeration. Partial zero counts print unknown; unavailable results print no numerical clean counts. Complete empty enumeration may say No annotations. Unknown severity and malformed records are partial, never silently clean. Page/count/call/byte/display caps are explicit. More inline records and omitted summary lines are identified with links. Remote text is quoted; controls/newlines, backticks, angle brackets and trailer-looking tokens are escaped. Truncated fields use an ellipsis. Only validated numeric/head/repository provenance is printed as metadata.

Persistence uses the unchanged Wait.LastOutput JSON and domain.TaskWaitResult.Output path. Interactive WakeMessage and task wake Prompt receive the same saved summary. Failed delivery and settled replay retain the saved diagnostics without another GitHub collection. No schema or serialization path was modified.

Source map: internal/wait/github.go contains status fields, bounded gh execution and terminal integration; internal/wait/github_annotations.go owns provenance, enumeration, budgets and rendering. github_annotations_recheck.go owns the fixed REST/GraphQL consistency requests. github_annotations_test.go preserves the BEFORE regression and JSON forwarding test; github_annotations_controls_test.go exercises fake-API adversarial controls and actual task-bound wake delivery/recovery. Existing retry/gone/cancellation/mapping controls remain.
