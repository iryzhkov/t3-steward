# Internal M16 review admission/provenance contract

This enabling unit has no production callers. ReviewAdmissionService.Resolve derives an AdmissionSnapshot from loaded coordinator records; Freeze calls the existing SQLite FreezeReviewAuthority only after resolution succeeds. It is not full M16 and does not authenticate an operator.

## Trusted and untrusted boundaries

The request contains only run/task/attempt IDs and a trusted internal AdmissionPolicy: risk, criteria artifact ID, exact member ID/role/route/required choices, deciding count, diversity and round limit. There are no caller digests, family/tier, parent binding, project path, base or head fields. An internal parameter is a declaration, not proof of its origin. Later immutable public submission admission must authenticate and retain those choices before any public review requirements can be accepted.

The store loads a transactionally consistent CoordinatorRecords snapshot. The resolver requires exact run/task/workflow membership, task RunID, uniquely latest live declared attempt, claimed assignment/thread/project and no supervision activation. It derives thread, assignment ID/epoch, attempt revision and executor route. SQLite remains the final transactional identity/replay fence. Resolve is read-only; a failed provenance check never calls Freeze. Store errors remain refusals.

ProjectCatalog.Resolve supplies the repository URL and preparation metadata. The workflow must store a full lowercase immutable Git commit ID itself. Catalog default refs, branches and fresh workspaces refuse. FrozenAuthority.Repository remains workflow project identity, not the URL. The receipt retains the catalog URL. A commit string does not establish object existence, worker physical checkout, resolved live base or final HEAD; later trusted probes must establish those facts.

AdmissionCatalogSource is the narrow trusted configuration adapter contract. It must project the effective coordinator-authored worker provider model policies and project eligibility plus configured backlog_v2.review_routes metadata. It must never project worker observations, discovery/readiness, instance alias heuristics or executor-supplied classifications. AuthoredWorkers uses existing domain.WorkerInventory solely as a typed projection; Projects names authored eligibility, not an observed advertisement. Available, Connected, health, enrollment and quota are not considered. The interface's name is not authentication: coordinator wiring must establish origin. Missing adapters fail closed; there is no observations-as-authority fallback or production wiring in this unit.

Actual configuration contracts were reverified: config.CoordinatorFleet is explicitly authored authorization; effective BacklogV2.Workers provider Models/QuotaPool and Projects.Workers are projected in coordinatorWorkerAuthorization and coordinator runtime. ReviewRoutes provides configured family/tier. The mapped authoredModelAuthorized symbol is absent in this stack; domain.ModelAuthorized and existing validatePolicyCatalog supply the verified exact-model semantics instead. No main-package import or config/backlog import cycle is introduced.

## Retained criteria and canonical digests

Criteria must be an ID in both task and workflow input memberships, with matching run input membership. Duplicate IDs refuse. pinnedinput.NewManifest recomputes the complete bounded sorted name/size/SHA256 manifest and must match its stored digest. Every manifest entry must match exactly one retained submission input in workflow membership with the same run, empty task/attempt producer identity, name, size and hash. Prompt, workflow.yaml, output, foreign-run, unpinned, ambiguous and oversized criteria refuse. CoordinatorArtifactStore.Open verifies retained metadata/content; the resolver compares its metadata to the loaded snapshot and rereads at most MaxFileBytes+1, checking exact size/hash. The criteria digest is SHA256 of those bytes. The receipt binds artifact, run, workflow, task, name, size/hash and canonical manifest. Mutating the original source cannot change the retained copy.

PolicyDigest is SHA256 of compact encoding/json bytes of the fixed review-admission/v1 envelope in review_admission.go: normalized trusted policy (default round limit resolved), resolved project environment, canonical input digest, criteria binding and selected route classifications plus all matching authored grants. Members sort by ID; grants sort by their canonical digest; model lists and environment set collections sort. Setup command order remains meaningful. Unselected classifications and live readiness are excluded. Selected authored model-policy, catalog revision, quota binding, family/tier, project preparation and retained criteria changes affect the digest and frozen replay. It is explicitly distinct from a raw generated role-policy file digest; this unit does not read or retain that file.

Existing review.NewRequirements is the sole authority validator for roles, deciding count, two families, risky required independent critical reviewer and routine/risky round ceilings. Exact slash-containing models are split at the first slash only. Sole '*' authorizes concrete models through domain.ModelAuthorized; mixed wildcard policy and runnable '*' refuse. Missing or duplicate selected classification refuses. Returned manifest/member/environment/grant collections are detached from store/catalog/request slices.

## Storage and future enforcement

Equal admissions freeze/replay to the same canonical authority. Changed requirements, criteria/catalog policy digest or parent identity conflict under existing SQLite immutable storage. A changed current attempt revision also changes the derived binding; this unit does not silently reuse an older authority. No public Manifest/Task/Workflow/Attempt/wire/CLI/config schema was added or relaxed. Standalone review and accepted authority/title units remain unchanged.

Later enabling work must retain immutable public policy admission and authenticated configured-catalog adapter provenance; continue criteria/manifest retention and digest membership obligations; integrate trusted resolved-base and physical checkout/final-head evidence; then implement child submission, independent reviewer lifecycle, park/resume, retry/checkpoint backup, slot release, progress and completion/task-acceptance enforcement. There is no readiness/quota/provider-diversity waiver here and no cross-provider call. Separate lead-scheduled Sol/Astra medium reviews follow; this candidate does not self-accept.
